# Deploy Domain Services in Azure to replace Domain Controllers.


# what is Active Directory (AD)?

Active Directory (AD) is Microsoft's directory service for managing users, computers, and resources in a network. It's essentially a centralized database and set of services that controls who can access what in an organization.

What it stores:

User accounts (name, password, email, group memberships)
Computer accounts
Groups and organizational units (OUs)
Security policies

Core components:

Component	                         Purpose
Domain Controller	                Server that runs AD
Domain	                            Logical boundary (e.g., company.local)
Forest	                            Top-level container of one or more domains
OU (Organizational Unit)	        Folder-like structure to organize objects
Group Policy (GPO)	                Rules pushed to users/computers

# What is Domain Controller (DC)

DC is a server running Microsoft's Active Directory (AD) that authenticates and authorizes users, computers, and other resources in a Windows domain network.

Core functions:

Authentication — verifies identity (username/password, Kerberos tickets) when users log in
Authorization — enforces who can access what resources
Directory storage — holds the AD database (NTDS.dit) with all objects: users, groups, computers, policies
DNS — typically runs DNS so domain names resolve within the network
Group Policy — distributes and enforces security/configuration policies to all domain members
Replication — syncs changes across multiple DCs for redundancy

# 2. What is Azure Entra Id manage Domain Services (New Way)?

Azure Entra Id manage Domain Services is:

A managed domain service provided by Azure — Microsoft runs the domain controllers for you.

✅ Domain join (VMs can join domain)
✅ User login (username/password)
✅ LDAP (apps can query users)
✅ Kerberos / NTLM authentication
✅ Group Policy (GPO)

Key concepts:

A domain is the logical boundary (e.g., company.local)
A forest is a collection of domains sharing a schema
LDAP is the protocol used to query the directory
Kerberos handles ticket-based authentication

So our apps and servers still work like before.

# Why Do We Need Domain Services?

Let’s say we are deploying apps in Azure:

Without Domain Services:
You need to:
Create VMs
Install AD DS
Maintain domain controllers
Handle replication, backup, patching

That’s a lot of work.

With Domain Services:
Azure gives you:
A ready-to-use domain
Highly available
Secure by default

You just use it, not manage it.

Step 19: Prepare Identity Structure:

Note: Before we start joining servers and deploying apps, we need to organize identities inside our domain service

1. OUs (Organizational Units)
What they are: Logical “folders” inside your domain to organize:
Servers
Users
Groups
Why you need them:
Apply Group Policies (GPOs)
Delegate access
Keep environment clean

What we should create:

For our setup, keep it simple:

corp.configio.com
│
├── Servers
│    ├── WestUS
│    └── UKSouth
│
├── ServiceAccounts
│
└── Users (optional if synced from Entra ID)

Example use:
Put Ops VM → Servers/WestUS
Put UK VMs → Servers/UKSouth

2. Service Accounts:
What they are: Special user accounts used by applications/services instead of real people.

3. Security Groups:

What they are: Collections of users or machines used to assign permissions.

How These 3 Work Together:
Example:
Create:
OU → Servers/WestUS
Group → SG-Server-Admins
Service account → svc-configio-app
Then:
Put VM in OU
Apply policy to OU
Give group access to server
App uses service account

Where You Do This:

Since you're using Domain Services, you’ll manage this from:

Domain-joined VM (like your Ops VM)
Tools:
Active Directory Users and Computers (ADUC)
