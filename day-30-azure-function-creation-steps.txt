Note: Let's start by understanding the workflow diagram.

1. so, when user uploads a file to an Azure Storage Account container.

2. then, Event Grid Detects the Upload

Basically, Azure Event Grid continuously monitors the Storage Account.

Whenever a new file (blob) is uploaded, Event Grid automatically generates an event.

This event is then sent to Azure Functions as a trigger.

3. After that, Azure Functions receives the event notification along with event details such as:

File name
Upload time
Container information
Other metadata

The Azure Function then invokes Azure Communication Services (ACS) by passing the complete event data.

4. Then, Azure Communication Services processes the request and sends an email notification.

Basically, Azure Email Communication Service handles the email delivery in the Communication service.

5. Finally, the user receives the notification in email.

> Azure Event Grid Topic: A topic is an endpoint that receives events from publishers and makes them available to subscribers for event processing. It serves as a logical channel for a collection of related events. It acts as the entry point for events before they are routed to subscribers.

> we cannot see the topic name here, Because, we are using a system topic, not a custom topic.

there is three types of Event Grid topics:

1. System Topic: it is created Automatically  for Azure services that publish events such as.

Storage Account
Azure Resource Group
Azure subscription
Key Vault, etc.

# in this case:

✔ No topic name needed in your command
✔ Azure automatically creates system topic for Storage Account internally.
✔ You only reference --source-resource-id
✔ Topic management is hidden for system events

2. Custom Topics:

it is Created by you for your own applications. in the custom topic, Your application publishes custom events to the topic.
Event Grid then distributes them to subscribers such as:
Microsoft Azure Functions
Webhooks
Logic Apps
Service Bus queues

3. Partner Topics:

it is Used by third-party SaaS providers that integrate with Event Grid.

Examples include external services sending events into your Azure environment.

53. Now, team, I want to give you a short overview of the function code.

Let’s go back to the Function App and understand the function features and code.

1. So in the function code, first we are Importing a required libraries:

logging → Used to print logs (success/error messages)

os → Used to read environment variables (config values)

azure.functions → Provides Azure Functions runtime support

EmailClient → Used to send emails via Azure Communication Services

2. Creating a Function App instance

app = func.FunctionApp()

it will Initializes the Azure Function App

This is the main container where all triggers/functions are registered

3. Then, we are Defining Event Grid Trigger Function

@app.event_grid_trigger(arg_name="event")
def EventGridBlobTrigger(event: func.EventGridEvent):

This tells Azure:
Run this function when an Event Grid event occurs”
event contains details about the storage event (blob created/deleted/etc.)

4. data = event.get_json()
Extract event data
Converts the incoming Event Grid event into JSON format

5. blob_url = data.get("url")

This will Extracts the full URL of the blob that triggered the event

6. blob_name = blob_url.split("/")[-1] if blob_url else "Unknown"

it will Extract blob name from URL

Basically it will Takes last part of URL as file name

Example: file1.txt from full URL

If URL is missing → sets name as "Unknown"

7. 
conn_str = os.getenv("ACS_CONNECTION_STRING")
sender = os.getenv("ACS_SENDER_ADDRESS")
recipient = os.getenv("TO_EMAIL")

It will get these value from environment variables of Azure Function App settings.

8. if not all([conn_str, sender, recipient, blob_url]):

Here, Validating required values. such as:
Checks if any required value is missing
If missing:
logs error
stops execution

9. client = EmailClient.from_connection_string(conn_str)
Create Email client and Connects to Azure Communication Services Email system

10. 
message = {
    "senderAddress": sender,
    "recipients": {"to": [{"address": recipient}]},
    "content": {
        "subject": "Blob Created Notification",
        "plainText": f"New blob created:\n\nName: {blob_name}\nURL: {blob_url}"
    }
}

This line:

Prepares email content:

From address (sender)
To address (recipient)
Subject line
Body with blob name and URL

11. client.begin_send(message).result()

It will Sends email using Azure Communication Services
.result() ensures execution waits until email is sent

12. logging.info("Email sent successfully")

It will store success message in Azure logs

13. except Exception as e:
    logging.error(f"Email send failed: {e}")
	
This is use for Error handling.
If anything fails:
catches error
logs failure reason
