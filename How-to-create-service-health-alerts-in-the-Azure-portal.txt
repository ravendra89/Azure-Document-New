1. Service Issues

If you click on service issues, here you can see that there is No active service issues.

Definition: Service issues refer to any ongoing or past problems affecting the availability or performance of specific Azure services in a particular region.
This could include disruptions, outages, or degraded service performance caused by internal Azure problems (e.g., data center failures, network disruptions, etc.).

what is Use Case: We can use service issue feature to monitor service issues to stay informed about problems that could impact the operation of our services hosted on Azure.

Example: A particular Azure region experiencing downtime for virtual machines, storage, or networking services.

2. Planned Maintenance.
Cloick on Planned Maintenance, you can see here, No planned maintenance events found, that means, there is no Upcoming maintenance windows and scheduled updates.

Definition: Planned maintenance is scheduled work that Microsoft Azure will carry out on Azure infrastructure or services.
 This might involve updates, hardware replacements, system patches, or upgrades. These are usually communicated ahead of time so that customers can plan accordingly.

Use Case of Planned Maintenance: You can use this information to prepare for periods when certain services may be temporarily unavailable or degraded due to planned updates.

Example: A planned upgrade to the Azure SQL Database service in a region, which may result in temporary downtime for customers using that service.

3. Health Advisories: you can see here currently, I dont have any health advisories from Azure side.

Definition: Health advisories provide recommendations or warnings from Microsoft related to known issues, security vulnerabilities, or best practices
for maintaining the health and security of your Azure resources. These may not always indicate an immediate problem but serve as a proactive measure.

Use Case: To stay ahead of potential problems and adjust configurations or practices before they affect your Azure services.

Example: A security vulnerability discovered in a specific Azure service or a recommendation to update to a newer, more secure version of a service.

4. Security Advisories: I dont have any security advisories.

Definition: Security advisories focus specifically on vulnerabilities, threats, or security-related incidents that could affect Azure services or your workloads running on Azure.
 These alerts provide information on how to mitigate or resolve security risks.

Use Case: Security advisories are crucial for maintaining a secure environment, and you would monitor them to apply recommended patches, configuration changes, or other actions to protect your Azure resources.

Example: A critical security vulnerability in a specific service, such as a bug in Azure Active Directory or a service that allows unauthorized access.

5. Billing Updates: you can see here, No billing updates found

Definition: Billing updates inform you about changes to your billing cycle, pricing, charges, or subscription status.
 These updates may also include information about billing errors or discrepancies.

Use Case: To ensure you are aware of any changes in your Azure costs or billing structure, as well as to address any potential issues with your account's financial status.

6. Health History:

Definition: Health history provides a historical view of past service issues, planned maintenance events. It allows you to review any incidents that affected
 your Azure environment in the past.

Use Case: To analyze past incidents and their impact on your services, and to identify patterns that may help in troubleshooting or in improving future resilience.

Example: Viewing a timeline of past outages in a region or checking the performance impact of past planned maintenance activities.

7. Resource Health:  

Definition: Resource health shows the current health status of your individual Azure resources (e.g., Virtual Machines, Databases, Storage Accounts).
It provides specific details on whether your resources are running as expected,  or any outage affecting them.

Example: Checking the health of a specific virtual machine in our subscription that may be experiencing connectivity issues.

2. In the Service Issues panel, click on Create service health alert to open a new window where you fill in the information required to create the alert.

3. Scope level- You can select either Subscription or Directory (Tenant).

> If you select Directory (Tenant), it will include all the subscriptions within that directory. This means you can monitor and create service health alerts
 for all existing subscriptions and the resources within them.

> If you select Subscription as the scope level, you can monitor and create service health alerts for a single subscription and the resources within that specific subscription.

4. Here, we need to define condition.
